# SIMB-AD PharmaGraph — демо-прототип

**От подходящей аптеки до прозрачного результата кампании.**

Интерактивный прототип для хакатона: retail media для онлайн-аптек (Казахстан — основной рынок, Россия — дополнительный).
Безрецептурные товары, БАД и wellness, без рецептурных препаратов.
Бренд платит платформе за клики, аптека получает долю рекламного дохода и компенсацию скидки за каждый выкуп.

Все участники, товары, операции и результаты вымышленные. Реальных интеграций, выплат и платежей нет.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # юнит-тесты доменной и финансовой логики
npm run typecheck
npm run build      # production-сборка в dist/
```

Данные хранятся в `localStorage` браузера. Кнопка «Сбросить» в верхней панели возвращает демо к исходному состоянию (с подтверждением).

## Три роли (переключаются без входа)

- **Бренд DemoCare**
  - Возможности: где запускать, с основаниями и графом «Бренд → Товар → Аптека → Город».
  - Кампании с понятными причинами остановки.
  - Результаты от клика до выкупа.
  - Пример оценки прироста.
- **Аптека** («Арна», Алматы; «Шуақ», Астана)
  - Предложения: подтвердить или отклонить. Подтверждение фиксирует цену.
  - Расчеты: рекламный доход и подтвержденные компенсации, резерв отдельно.
  - Ассортимент: ручное редактирование и CSV-импорт с предпросмотром и построчными ошибками.
- **Витрина**
  - Рекламная карточка с пометками «Реклама» и «Скидку финансирует бренд».
  - Тестовый заказ без персональных и платежных данных.
  - Демо-выкуп, отмена и возврат.

## Сценарий демо (кнопка «Сценарий демо»)

1. Найти, где запускать
2. Создать кампанию (100 000 ₸ реклама, 50 000 ₸ скидки, CPC 100 ₸, скидка 500 ₸)
3. Аптека подтверждает
4. Покупатель кликает рекламу
5. Заказ и выкуп
6. Результаты кампании
7. Возврат
8. Остаток закончился
9. Пример оценки прироста

У каждого шага есть «Перейти» и «Выполнить»: показать вручную или прокрутить сценарий за пару минут.

## Финансовая логика

- **Клик (CPC 100 ₸).** Аптеке 70 ₸ (70 %), платформе 30 ₸. Клик тарифицируется один раз за сессию покупателя и не сторнируется.
- **Заказ.** Резервирует 1 шт. и скидку из бюджета скидок.
- **Выкуп.** Резерв становится подтвержденной компенсацией аптеке. Пример: 600 ₸ расхода бренда = 70 ₸ аптеке за клик + 500 ₸ компенсации + 30 ₸ платформе.
- **Отмена.** Резерв и единица товара возвращаются.
- **Возврат.** Компенсация сторнируется, единица возвращается в остаток, клик остается. Итог: 100 / 70 / 0 / 30.
- **Идемпотентность.** Каждое событие имеет идентификатор, повтор не меняет итоги. В витрине есть кнопка «Повторить последнее событие».
- **Показ останавливается с конкретной причиной.**
  - Причины: нет подтверждения, вне дат, ручная пауза, остаток 0, рекламный бюджет меньше CPC, бюджет скидок с учетом резерва, изменилась цена (нужно повторное подтверждение).
  - Показ возобновляется сам, когда причина исчезает. Ручная пауза не снимается автоматически.
  - Исчерпанный рекламный бюджет и закончившийся период не восстанавливаются: бренд завершает кампанию и запускает новую.

## Архитектура

```
src/domain/    чистые функции (state, payload, now, eventId) → Result: правила, действия, метрики, леджер, CSV, сид
src/store/     Zustand-стор, версионированное сохранение в localStorage, команды и навигация
src/features/  экраны: brand/, pharmacy/, storefront/, scenario/
src/ui/        примитивы, графики, верхняя панель, таблица операций
```

Стек: React 19, TypeScript (strict), Vite, Tailwind CSS v4, Zustand, lucide-react, Vitest.

## Ограничения прототипа

- Только клиент: нет бэкенда, API, реальных выплат, ML и карты.
- Один формат: карточка в каталоге, CPC, фиксированная скидка в тенге. Одна аптека и один товар на кампанию, одна штука в заказе.
- Данные синтетические, оценка прироста — иллюстративный пример без статистических тестов.
- Только светлая тема.
